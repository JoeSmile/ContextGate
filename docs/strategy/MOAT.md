# 护城河与生存率(Moat & Survival)

> 更新:2026-08-02。来源:战略讨论结论。性质:认知层 —— 回答「凭什么活下来、什么抄不走」。

## 1. 核心结论:代码不是护城河,位置才是

项目从立项到成型只有一周,工作量和技术含量可被大厂团队轻松碾压 —— 但「被碾压」和「活不下来」是两件事。
护城河不取决于代码多强,取决于在大厂够不着的地方有多深。

GPT-5 抄走代码,抄不走这四样:

| # | 抄不走的东西 | 说明 |
|---|--------------|------|
| 1 | **脑子里的东西** | 国企怎么决策、采购流程怎么走、合规红线在哪、谁能拍板、制度怎么理解 —— 现场经验,训练数据里没有 |
| 2 | **位置** | 进了技术中心,就是「从内部懂 AI 治理的人」;体制内立项/预算/决策在围墙里,模型再强也进不来 |
| 3 | **落地记录** | 真实跑起来的内部项目 + 审计报告 + 领导认可,时间堆出来的,无法复制 |
| 4 | **品牌** | 名字绑定的个人品牌:技术文章 + 开源项目 + 署名;面试官搜到,信任状当场成立 |

**反直觉观点:** 做「治理层」恰好不怕模型迭代 —— 治理层的价值不在模型能力,在流程、审计、合规、位置。
模型会越来越强(人人都能用),但「谁能证明每次 AI 调用都合规可审计」的答案不在模型手里,在治理体系手里。
大厂抄了代码说明方向对了,这是验证不是威胁。

## 2. 大厂打不了你的三个地方

1. **垂直场景** —— 大厂必须做通用平台(服务最大市场),每个客户的需求只做到 80 分;一个国企的「制度问答 + 审批 + 审计 + 数据不出域」定制需求,大厂不会为一个客户改产品,我们会。结构性缝隙,不是技术差距。
2. **贴身交付** —— 国企采购的真实流程:有人对接、能改、能陪跑、出了问题有人管。大厂走渠道和工单,我们能做到「一个电话,当天改完」。AI 辅助让单人响应速度接近一个完整团队。
3. **本地化合规** —— 等保、密评、「数据不出域」:大厂 SaaS/云产品天然难做(数据在他们那);我们的架构从第一天就是私有化部署 + 加密 key + 审计留痕。合规不是功能,是准入证。

## 3. 三个不对称优势(别浪费)

1. **速度** —— 一个人 + AI 工作流一周做出 23 个任务的企业级框架;「单人团队」产能是独有资产,大厂十个人的沟通成本抵消不了。
2. **成本结构** —— 几乎零成本运营,可以打任何价格战,也可以免费陪跑换案例;有资格「先做出来再谈钱」。
3. **场景知识** —— 懂国企 CIO 的痛(审计、合规、可溯源),这是大厂产品经理坐办公室想不出来的。

## 4. 生存率公式(按权重排)

```
第一个付费客户 > 垂直场景做深 > 合规交付能力 > 个人品牌/内容 > star
```

前两项占 80%。一个愿意付钱的国企客户顶一万个 star,而且它带来第二个客户。

## 5. 接下来 30 天走法

1. **停止横铺功能**(技术负债 + 方向漂移),把现有能力固化成「能演示、能交付」的状态 —— 证据包就是干这个的
2. 用全链路 Demo 剧本(7 分钟那套)找第一个真实场景:亲戚朋友的企业、之前的客户、任何能接触到 CIO 的渠道,免费做 PoC 换案例
3. 选一个垂直场景做到 95 分(制度问答:知识库 + RAG + 审批 + 审计 + 本地模型一条链)—— 做深了就是 ai-platform 的雏形
4. 内容路线同步走,定位是「销售漏斗」不是「兴趣爱好」:每篇文章都是给 CIO 看的信任状
5. 30 天后复盘:有没有真实用户在用?有没有「非你不可」的反馈?有 → 继续深挖;没有 → 场景选错了,换场景,不换决心

## 6. 与 v2.0 的关系

护城河在功能层面的落点 = `docs/V2_PROPOSAL.md` 的 7 个方向:

- 2.1 合规报表 —— 审计是护城河第一层,报表是「最后一公里」
- 2.2 护栏配置化 —— 竞品几乎无人做全,差异化卖点
- 2.3 预算配额 —— 比 LiteLLM 多「策略」一层
- 2.4 数据不出域 —— 云厂商做不了(利益冲突),国产替代刚需
- 2.5 场景样板 —— 卖「治理 + 场景贯通」的样板间,不卖模板

**一句话:护城河 = 位置(个人)+ 治理证据链(产品)+ 垂直场景(市场),三者互相强化。**
