# 国企技术中心求职与品牌打法(Job Hunt & Brand)

> 更新:2026-08-02。目标:找国企技术中心岗位,从内部推动 NexusAI。性质:行动层。
> 核心逻辑:不是在开源创业,是在打一场「国企内部推动」的仗 —— 求职、品牌、内容全是这一仗的武器。

## 1. 面试武器(三件套)

1. **架构讲解** —— 能讲清治理层定位:pgvector + LangGraph DAG + LangFuse + RBAC0;讲清「为什么治理层不怕模型迭代」
2. **Demo 能跑** —— 证据包(MANUAL_TEST)+ 全链路 Demo 剧本(认证 → 意图 → RAG → 流式 → admin → 成本 → LangFuse span)
3. **一页纸提案** —— 标题都想好了:**「集团 AI 中台的治理层建设」** —— 治理/合规/审计/数据不出域,国企技术中心现在最缺的叙事,市面上没有几个人能讲

## 2. 一页纸提案框架(给技术中心领导看)

> 结构先定好,内容填「你的场景理解」。这份文档本身就是面试谈资。

```
标题:集团 AI 中台的治理层建设
1. 现状痛点   —— AI 应用散、模型杂:谁在用、用了什么、花多少钱、输出安不安全、出问题能不能溯源?
2. 方案       —— 一个治理网关:认证/护栏/审计/成本/路由/观测,执行层随便换(Dify/自研/国产模型),治理证据链不断
3. 为什么是治理层 —— 模型会越来越强,「合规可审计」的答案不在模型手里,在治理体系手里
4. 落地路径   —— 先一个一把手支持的场景(如集团制度知识库问答)立口碑,再顺势讲「这个需要治理层」
5. 风险与对策 —— 数据出境红线(私有化 + 本地模型不出域)、国产化替代(国产模型可接)
6. 下一步     —— 3 个月 PoC,小成本验证
```

## 3. 内部推动的正确顺序

**先有业务价值,再有基础设施。**

1. 别一上来推平台 —— 先找一把手支持的场景(比如集团制度知识库问答)
2. 小项目 3 个月立口碑 —— 「这个系统解决了我的问题」比任何架构图都有说服力
3. 再顺势讲「这个需要治理层」 —— 从场景反推基础设施,立项才有人支持

项目天然契合这个叙事:私有化、审计留痕、四角色权限、数据不出域、国产模型可接 ——
每一项都踩在国企 AI 合规的红线上,这比技术先进性值钱。

## 4. 品牌内容路线(一鱼三吃)

同一份材料三份用途:社区技术文章 / CIO 售前信任状 / 面试谈资。

- **定位**:内容 = 销售漏斗 = 求职杠杆,不是兴趣爱好
- **第一篇**:署名绑定 NexusAI,讲一个域的真干货(治理层、护栏纵深、审计链路任选)
- **节奏**:每篇一个域的深度内容,拒绝注水课程,要真实工程价值
- **素材来源**:证据包实测数字 + 踩坑记录 + 合规清单(文档化脑子里的东西的副产品)
